## Resumen ejecutivo

A04-R3 cierra el circuito completo de decisiones y aplicación histórica de A04. Donde A04-R1 detectó once áreas de defecto y A04-R2 las corrigió parcialmente, A04-R3 demuestra que **cada código de incidencia tiene un productor estable, cada decisión de resolución tiene un consumidor real, cada tipo de acción tiene productor y escritor, y la reconstrucción + plan + Apply forma un circuito cerrado que llega a la base de datos y a la auditoría**.

## Arquitectura de la solución

### Identidad efectiva (single source of truth)
- `EffectiveCompanyIdentity` + `EffectiveClientIdentity` resueltos **una vez** en `BuildLegacyImportPlan::hydrate()`
- Toda la cadena (reconstrucción → plan → Apply) usa la **misma** identidad
- Clave centralizada: `ImportDecisionSet::clientIdentityKey()`

### Plan invalidation sincrónico
- Resolución de incidencia → `plan_revision++`, `plan_digest = null` (sincrónico, en transacción)
- Rebuild job avanza revisión y computa digest
- `apply` valida `plan_revision` + `plan_digest` bajo `FOR UPDATE` → `409` si stale

### Decisiones consumidas (no inertes)
| Decisión | Consumidor | Efecto |
|---|---|---|
| `treat_as_duplicate_of` | `BuildLegacyImportPlan::hydrate()` | Fila excluida de la reconstrucción |
| `keep_both` | idem | Ambas filas se conservan |
| `link_existing_client` | `EffectiveClientIdentity::resolve()` | Identidad efectiva = cliente existente |
| `use_company_nit` | `EffectiveCompanyIdentity::resolve()` | NIT efectivo = el elegido |
| `create_entity` | `ImportDecisionSet::createdEntityName()` | Acción `CreateSocialEntity` emitida |
| `accept_source_amount` | `rateActions()` + `writeRate()` | Rate actualizado in situ |
| `accept_existing` / `overwrite_with_source` | `ImportDecisionSet::approvedFields()` | Campos aprobados escritos; resto conservado |
