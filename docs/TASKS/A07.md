# A07 — Cloud Assistant (Remediación Final Verificada)

## Resumen

A07 entrega un asistente de IA integrado en Consultora DH con:
- Conversaciones persistentes con memoria acotada
- Herramientas de solo lectura (ejecutan inmediatamente) y de escritura (producen propuestas)
- Confirmación humana requerida para cualquier escritura
- Generación de artefactos privados (PDF, DOCX, XLSX, CSV, MD, TXT)
- Búsqueda web y fetch con protección SSRF completa
- MCP (Model Context Protocol) JSON-RPC 2.0 compatible
- Frontend en `/asistente` con permiso `ai.use`

## Cambios Principales vs A06

### Seguridad
- **Frontera de autenticación global restaurada**: `Route::middleware(['auth', 'auth.session', 'user.active', 'throttle:api'])` en lugar de `["web"]`
- Rutas AI requieren `can:ai.use` en middleware, no solo en controlador
- Portal, soporte, push, presence usan middleware autenticado correcto

### AI Assistant Core
- `AiAssistantController` fijado: `index(Request $request)`, imports correctos, ownership checks, una persistencia por turno
- `AiAssistantService` reescrito: inyecta `AiToolRegistry` y `AiProviderResolver`, usa `definitions()`, `get()`, `executeRead()`, `executeWrite()`
- Memoria de conversación: persiste user + assistant, envía historial acotado (6 pares), no duplica pregunta actual

### Tool Registry
- Eliminado `ReportArtifactTool` (no existía)
- Añadidos 16 herramientas reales:
  - **Negocio existente**: client_search, client_summary, receivables_summary, client_account, operational_tasks, report_preview, support_summary
  - **Escritura (propuestas)**: create_operational_task, create_report
  - **Web**: web_search (SearXNG configurable), web_fetch (SSRF completa)
  - **Artefactos**: create_artifact (PDF, DOCX, XLSX, CSV, MD, TXT)
  - **Documentos**: document_search, document_read (reusa autorización A05)
  - **Automatizaciones**: automation_vocabulary, create_automation_rule, activate_automation_rule, deactivate_automation_rule

### Web Search
- Reemplazado DuckDuckGo hardcodeado por proveedor SearXNG configurable
- Config: `AI_WEB_SEARCH_ENABLED`, `AI_WEB_SEARCH_BASE_URL`, `AI_WEB_SEARCH_TIMEOUT_SECONDS`
- Salida: title, url, domain, snippet, published_at

### Web Fetch (SSRF Completa)
- Rechaza credenciales en URL
- Resuelve DNS y valida **cada** IPv4/IPv6 resuelta
- Rechaza: loopback, RFC1918, link-local, metadata (169.254.169.254), rangos reservados/privados, nombres Docker/internos
- Valida **cada** target de redirección antes de seguir (máx 5)
- Timeout acotado, bytes descargados acotados (500KB), solo text/html seguro
- Extrae texto legible, no HTML/JS ejecutable

### Artefactos Reales
- Implementación real usando Dompdf + PhpOffice (PhpWord, PhpSpreadsheet)
- Persistencia `AiArtifact`: owner user, conversation nullable, display_filename, mime, format, UUID storage_path, size, created_at, expires_at
- Almacenamiento privado, endpoint de descarga autorizado, sin rutas controladas por modelo/navegador

### Documentos
- `document_search` / `document_read` reusan autorización y almacenamiento privado A05
- Sin rutas de filesystem directas

### Automatizaciones
- `automation_vocabulary` expone vocabulario A06 oficial (triggers, conditions, actions)
- `create_automation_rule` construye regla A06 válida, requiere confirmación
- `activate_automation_rule` / `deactivate_automation_rule` con proposals
- Ejemplo funcional: "Cada lunes revisa clientes vencidos y crea una tarea"

### MCP (Model Context Protocol)
- JSON-RPC 2.0 endpoints: `initialize`, `tools/list`, `tools/call`
- Tokens MCP persistentes: `user_id`, `name`, `token_hash` (SHA-256), `expires_at`, `last_used_at`, `revoked_at`
- Token raw devuelto **solo una vez** al crear
- Autenticación: Bearer raw_token → hash → match stored hash
- Verificaciones: existe, no expirado, no revocado, usuario activo, usuario autorizado
- Nunca selecciona "primer usuario"
- Gestión tokens: `POST/GET/DELETE /api/mcp-tokens` (requiere `mcp.tokens.manage`)
- Write tools vía MCP crean proposals normales, no mutan estado directo
- Documentación configuración OpenCode incluida

### Frontend
- Ruta `/asistente` añadida con `permission: 'ai.use'`
- Navegación integrada en sidebar (icono bi-robot, orden 70)

- UI: lista conversaciones, nueva conversación, historial, envío mensaje, loading/error/provider unavailable, fuentes web, descarga artefactos, propuestas pendientes, confirmar/rechazar
- Sin `v-html` para contenido AI/web no confiable
- Test Vitest enfocado creado

### Propuestas — Prueba de Exactamente-Una-Vez
- Test real: model/tool request → create_operational_task proposal → NO task → confirm → UNA task → segundo confirm rechazado → sigue UNA task
- Tests adicionales: propuesta ajena rechazada, expirada rechazada, rechazada no ejecutable, argumentos almacenados ganan a cambios navegador, permiso revocado antes de confirmar = sin mutación

### Provider / General LLM Tests
- HTTP fakes: respuesta general sin tools, primary success, retryable primary failure → fallback, auth/bad request no fallback inútil, claves ausentes de status/log/audit, historial en orden correcto, tool result vuelve al modelo para síntesis final
- Sin proveedor real externo en tests automatizados

### Operaciones Finales (Backup/Restore/Load/Production)
- **Backup**: PostgreSQL + almacenamiento privado, scripts versionados/runbook, timestampados, destino seguro, retención, sin secretos en output, nonzero en fallo
- **Restore Proof**: restore DB en BD disposable, restore archivos en dir disposable, verifica schema/archivos/checksums, borra targets disposable, nunca sobre desarrollo
- **Load**: script/test carga enfocado con fake AI provider, ejerce API autenticada, mensaje AI, MCP read, endpoint business read-heavy representativo, registra concurrencia/errores/p50/p95
- **Production**: verifica trusted hosts, secure cookies/proxy/HTTPS, queue, scheduler, Reverb, AI config, MCP, search, health, logs, cache commands, backup/restore, docker compose config
